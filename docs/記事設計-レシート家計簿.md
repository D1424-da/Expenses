# 記事設計：核キーワード「レシート家計簿」

キーワードプランナー（2025-08〜2026-07）の実データと、GA4・Search Console の
実績から設計したもの。**推測ではなく数字の裏付けがある部分と、無い部分を
分けて書く。**

## なぜこの核なのか

サイト内の記事1本あたりの成績（GA4 90日）:

| 種類 | 本数 | 1本あたり表示 | 1本あたりクリック |
|---|---|---|---|
| アプリ・ツール系 | 16本(18%) | **11.6** | **0.33** |
| 節約・食費系 | 17本(19%) | 5.9 | 0.00 |
| レシピ・献立系 | **46本(52%)** | 3.6 | 0.11 |

**記事数が最も多いレシピ・献立系が最も効率が悪い。** 上位（6〜10位）に
入っているのはすべてツール系で、なかでもレシート関連が最高順位だった
（`receipt-ocr-how-it-works` 6.1位、`receipt-kakeibo-basics` 9.7位）。

競合構造も有利:

- 「家計簿アプリ」… マネーフォワード・Zaim が独占。新規サイトに勝ち目なし
- 「レシピ」… クックパッド・デリッシュキッチンが独占。同上
- **「レシート家計簿」… 大手はレシート撮影を機能の一部としか扱っていない**

プロダクトの入口（レシート撮影 → OCR → 記録）とも一致する。

## キーワードの構造

| 検索数 | 語数 | 備考 |
|---|---|---|
| 5,000/月 | 20語 | **実質1キーワード**（語順違い） |
| 500/月 | 42語 |  |
| 50/月 | 257語 | ロングテール |

5,000/月の20語は `レシート家計簿` / `レシート家計簿アプリ` /
`家計簿アプリレシート` / `レシートで家計簿` … と語順が違うだけで、
Google は同一クエリとして扱う。**1本書けば20語すべてをカバーする。
20本書く必要はない。**

## 最も効率が良いのは競合他社名を含む語

61語・合計6,550件/月あり、**競合指数がほぼゼロ**。核キーワード（5,000/月・
指数55）より検索数が多く、競合は50分の1以下。

```
マネーフォワードレシート              500/月  指数 1
マネーフォワードレシート読み取り        500/月  指数 7
zaimレシート                        500/月  指数 2
レシーピ                            500/月  指数 1
マネーフォワードレシート読み取りできない  50/月  指数 0
マネーフォワードレシート精度            50/月  指数 0
```

「読み取りできない」「精度」は**既存アプリに不満を持つ人の検索**。
tohon が勝っているのと同じ構造（検索数が多いからではなく、競合がいないから
取れる）で、しかも「とは・違い」型で書ける。

### ⚠️ 2つの施策が同時に走っている

**9月上旬の確認では、数字が動いても「どちらが効いたか」は分かりません。**

```
第1弾（8/25） 記事76本の noindex     … サイト全体の評価に効く想定
第2弾（8/28） 未定義URLの404化       … クロール予算とURLの姿に効く想定
```

本来は1つずつ打つべきでしたが、第2弾はデザインレビュー側で
UX改修とまとめて用意されており、切り離すと `firebase.json` と `sw.js` の

読み方としては次のようにします。

- **数字が改善した** → どちらが効いたかは断定しない。**追加の施策は打たず**、
  さらに数週間見て定着するかを確認する
- **変わらない** → 第1弾（記事の量産判定）が効いていないと判断する材料になる。
  第2弾は未定義URLの話なので、そもそも84件の「クロール済み・未登録」には
  直接効かない
- **第2弾の効果は「クロール済み・未登録」ではなく、クロール統計
