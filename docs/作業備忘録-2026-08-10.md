## 4. Firebase ログイン不能バグ修正

### 問題
Googleリダイレクトログイン直後、`onAuthStateChanged` がトークン確定前に発火し `Missing or insufficient permissions` エラーでFirestore購読に失敗していた。

### 対応（`static/app.js`）
```javascript
// リダイレクトログイン直後にトークンが未確定の場合があるため
// Firestoreを購読する前に強制リフレッシュして権限エラーを防ぐ
await user.getIdToken(/* forceRefresh= */ true).catch(() => {});
subscribeMonth(_onSnapshotUpdate);
```

## 5. CI/インフラのコスト最適化

複数アプリで GitHub Actions を同時運用しているため、無料枠の消費を抑える対応。

| 項目 | 変更前 | 変更後 |
|---|---|---|
| `lighthouse.yml` | PR/push毎回自動実行（1回5〜8分） | 手動実行のみ（`workflow_dispatch`） |
| `test.yml` | PR + main push で実行 | PRのみ |
| Render無料プラン | 15分アイドルでスリープ→初回OCRが30〜60秒待ち | `keep-alive.yml` で10分毎にping、スリープ防止 |
| ブログのキャッシュ | `no-cache, max-age=0`（毎回再取得） | `/blog/*.html` は1日、`/blog.html`は1時間キャッシュ |
| Firestore購読 | タブ非表示中も購読継続 | `visibilitychange` で非表示時に購読停止、復帰時に再開 |

push 1回あたりのActions消費: 約12〜15分 → 約2〜3分に削減。

### keep-alive.yml のバグ修正
GitHub Actionsの `run:` はデフォルト `bash -e`。`STATUS=$(curl ...)` のcurl自体が失敗（DNS/タイムアウト等）すると代入全体の失敗として扱われ、ジョブが異常終了していた。curl失敗時は `"000"` にフォールバックするよう修正。
