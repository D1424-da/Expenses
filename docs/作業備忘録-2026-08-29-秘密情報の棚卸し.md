## `firebase-config.js` の `apiKey` は消さない

同じ `AIza` で始まるので混同しやすいが、**Firebase の `apiKey` は公開前提の値**で、
ブラウザに配信されるので隠せないし隠す必要もない。安全性は Firestore の
セキュリティルールと Authentication が担保する。

**消すと動かなくなるだけ。** 現在 `static/firebase-config.js` に残っている1つは
これに当たる。

紛らわしくなった原因は、**同じキーを Firebase の `apiKey` と `GEMINI_API_KEY` の
両方に使っていた**こと（`ae4408d8`）。Gemini API が有効なキーがブラウザに配信されて
いたので、公開リポジトリでなくても漏れていた。**用途ごとにキーを分けること。**

## 走らせ方（次に確認するとき）

既知の形を正規表現で探す方式。`AIza` / `sk_live_` / `whsec_` / `ghp_` /
`AKIA` / `xox[baprs]-` / `-----BEGIN PRIVATE KEY-----` / 資格情報つきの
接続URL / `secret_key=`〜 の代入。全コミットの追加行だけを見る。

```
git rev-list <ref> → 各コミットを git show --unified=0 → 追加行(+)を照合
```

`dummy` `example` `your-` `process.env` などを含む行は除外する（除外しないと
設定例で埋まって読めない）。**そのぶん、そういう語を含む本物は見逃す。**

**「見つからなかった」は「無い」ではない。** 形に特徴の無い秘密（ランダム文字列の
パスワード等）は取りこぼす。

## 公開・非公開の判断（この回で整理したもの）

**公開にする動機は「Actions が無料になる」の1つだけ。** private リポジトリの
Actions は課金対象で、8月は全体で5,752分・$11.57 かかっていた。ただし
**このリポジトリの1,759分は公開ゆえに $0** で、そこは得をしている。

```
公開にする   … 費用を払っていて、中身を読まれても困らないもの
非公開にする … 収益を生んでいる、または他人のデータ・実測値が入っているもの
```

**公開は git の履歴も全部公開する。** 現在のファイルに秘密が無くても、過去の
コミットに残っていれば読まれる——今回がまさにそれだった。**公開に切り替える前に、
必ず履歴を走査すること。** そして一度公開すると取り消せない。
